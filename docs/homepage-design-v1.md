# 首页设计稿 v1（只出方案，不动网站）

日期：2026-10-25 · 状态：待评审
目标：把首页从「输入框 + 数字 + 卡片堆」改成一篇讲清孵化逻辑的说明文。

---

## 0. 一句话结论

首页要回答三个问题，而不是陈列功能：

1. **什么念头值得孵化？**
2. **孵化到底对它做了什么？**
3. **我的苗圃现在长到哪了、下一步该孵哪一个？**

---

## 1. 核心逻辑：什么叫「孵化」

> 孵化不是收藏灵感，而是把一句模糊的话，经过四道工序，变成「今晚能做的第一步」，并持续记录它走到哪。

### 四道工序

| 工序 | 输入 | 动作 | 输出 | 通过标准 |
|---|---|---|---|---|
| **播种** | 一个词 / 一句话 / 一段对话 | 原样收进来，不评判、不要求成形 | 种子 seed | 能读出一件事 |
| **拆解** | 种子原文 | 写成九字段档案：问题 / 产出路线 / 差异 / 第一步 / 双评分 / 风险 | 档案 v1 | 四问能答：为谁、为什么是你、第一步、失败会怎样 |
| **试种** | 档案里的「最小第一步」 | 真的去做一次，把结果写回版本 | 实验记录 v2+ | 有可观察的结果，不是「感觉还行」 |
| **定级** | 实验结果 | 落地 / 继续 / 搁置，三选一 | shipped / proving / paused | **主动决定**，而不是慢慢忘掉 |

### 中间逻辑：不是所有念头都值得走到最后

三条判断标准，应该直接写在首页上：

1. **有人真的需要** —— 问题里有一个具体的人，不是「大家」
2. **今晚能试第一步** —— 第一步大到一周做不完，就是还没拆够
3. **和已有想法的关系清楚** —— 是新的、是延伸、还是重复（图谱负责这件事）

对应到产品的五态：seed → shaping → proving → shipped，paused 是主动搁置的旁路。

## 2. 首页信息架构（从上到下）

```
┌──────────────────────────────────────────────────────────┐
│ 页头：Logo · 看板 · 图谱 · 周回顾 · ⌘K                    │
├──────────────────────────────────────────────────────────┤
│ ① HERO                                                   │
│   左：主张 + 一句解释 + 今日状态（3 在生长 / 1 待拆）       │
│   右：种子→嫩芽→树 插画（唯一主视觉）                      │
├──────────────────────────────────────────────────────────┤
│ ② 什么念头值得孵化？（三条判断标准，图文并排）             │
├──────────────────────────────────────────────────────────┤
│ ③ 孵化是四道工序（横向流程，每道写清输入/输出）             │
├──────────────────────────────────────────────────────────┤
│ ④ 我的苗圃（真实数据 + 阶段条 + 一句「本周该处理哪颗」）     │
├──────────────────────────────────────────────────────────┤
│ ⑤ 现在要孵哪一个？（输入框 + 按待处理排序的卡片流）         │
├──────────────────────────────────────────────────────────┤
│ ⑥ 最近动态 / 周回顾入口（窄侧栏或底部一行）                 │
└──────────────────────────────────────────────────────────┘
```

**顺序的理由**：先讲「为什么值得」（②），再讲「怎么做」（③），然后才给「你的数据」（④）和「动手入口」（⑤）。这样第一次来的人能看懂产品，回来的人可以快速滚到 ④⑤。

## 3. 每块的内容、视觉、数据来源

### ① HERO

| 项 | 内容 |
|---|---|
| 主标题 | 把模糊的念头，孵成能落地的东西。 |
| 副标题 | 不是收藏灵感。每周挑一个，拆开、试一次，再决定继续还是放下。 |
| 今日状态 | `3 颗在生长 · 1 颗待拆 · 0 颗待试`（真实数据，无数据时不显示这一行） |
| 视觉 | 保留现有「种子→嫩芽→树」内联 SVG，但只在这里出现一次 |
| 交互 | 无按钮；整块是陈述，不做 CTA 堆叠 |

**为什么改**：现在 hero 是问候语 + 插画，信息量低。换成主张句后，第一次来的人 5 秒内知道这是干什么的。

### ② 什么念头值得孵化？

标题：**不是每个念头都值得养。先过这三道。**

三张卡（左图标 + 右文案，不是三个按钮）：

1. **有人真的需要** —— 说得出是谁、在什么场景下会用它；说不出来就先当种子。
2. **今晚能试第一步** —— 第一步必须小到 1–2 个晚上；大到一周，说明还没拆够。
3. **和旧念头的关系清楚** —— 新的、延伸的、还是重复的；重复的应该合并，不是再养一颗。

视觉：三张等宽纸卡，细线图标（人 / 脚印 / 分叉），无阴影堆叠。
数据：纯文案，不依赖数据库。

### ③ 孵化是四道工序

标题：**孵化不是打鸡血，是四道工序。**

横向四步流程（桌面 4 列，移动纵向）：

| 步骤 | 一句话 | 产物 |
|---|---|---|
| 播种 | 原样收进来，允许说不清 | 种子 |
| 拆解 | 写成九字段档案 | v1 |
| 试种 | 真的做一次最小第一步 | v2+ |
| 定级 | 落地 / 继续 / 搁置 | 状态 |

每步上方一个序号（01–04），下方一行灰色小字写「通过标准」。
视觉：一条 2px 主色细线串起四步，节点是圆点；不使用箭头图标堆叠。

### ④ 我的苗圃

标题：**我的苗圃**（右侧小字：`3 颗在生长`）

内容：
- 四个数字：入箱 / 本周新增 / 已拆解 / 已落地
- 一条阶段分布条（seed / shaping / proving / shipped / paused）
- **一句行动提示**：`本周有 1 颗停在「展开中」超过 14 天，建议试一次或搁置。`

视觉：数字用 mono 大号，标签 0.8rem；阶段条 2px 高，状态色只用在条和点上。
数据：`getHomeOverview()` 现有返回值即可；行动提示由 updatedAt 计算，不需要新表。

### ⑤ 现在要孵哪一个？

标题：**现在要孵哪一个？**（右侧：`3 条`）

- 单一自由输入框（已实现）
- 卡片流，**默认按「待处理」排序**：停在 shaping 最久 > seed 最新 > 其他
- 每张卡显示：原文两行 + 状态点 + 最后更新时间 + 版本数

视觉：输入框在上，卡片两列（桌面）/ 单列（移动），卡片不做悬浮跳动，只在 hover 时抬 1px。
数据：`listIdeas()` 增加一个排序参数即可，不改表结构。

### ⑥ 最近动态 / 周回顾

- 桌面放在 ⑤ 右侧窄栏；移动放到底部
- 只显示 5 条：创建 / 新版本 / 追问
- 底部一行入口：`本周回顾 → 看看哪颗睡了太久`

> 不是收藏灵感。每周挑一个，拆开、试一次，再决定继续还是放下。

> 我的苗圃

**输入区**
> 现在要孵哪一个？
> 一个词、一句话、一段对话——想记什么就写什么。

## 5. 视觉与动效规范

| 项 | 规范 |
|---|---|
| 主隐喻 | 种子→嫩芽→树，只出现在 hero 与四道工序，不重复装饰 |
| 字号 | page-title 2.05rem / section-title 1.28rem / body 0.95rem / meta 0.75rem |
| 颜色 | 青绿只用于「当前阶段」与主按钮；状态色只用于状态点和阶段条 |
| 留白 | 区块间距 56–72px；一屏最多两个视觉焦点 |
| 动效 | 页面进入：26px 横移 + 淡入；区块入场：8px 上移 + 80ms 递进；卡片不逐张浮动 |
| 图片 | 全部内联 SVG，离线可用；不使用外链图片 |
| 响应式 | ②③ 桌面横向、移动纵向；⑤ 桌面两列、移动单列 |

## 6. 与现有功能的映射

| 首页区块 | 现有能力 | 需要新增 |
|---|---|---|
| ① Hero | 现有插画 + overview | 文案替换；今日状态行 |
| ② 判断标准 | 无 | 纯静态内容 |
| ③ 四道工序 | 五态 + 九字段 | 纯静态内容 |
| ④ 我的苗圃 | getHomeOverview | 「该做决定」提示（updatedAt 计算） |
| ⑤ 输入 + 卡片 | IdeaInput + listIdeas | 卡片排序规则 |
| ⑥ 动态 / 周回顾 | 现有 | 无 |

**不需要改数据库，不需要新依赖。**

---

## 7. 明确不做

- 不做轮播、不做视频背景
- 不堆按钮：首页最多一个主按钮（提交）
- 不做无数据的装饰性统计
- 不在首屏放「最近动态」这类需要滚动才看得懂的内容
- 不为了动效而让卡片逐张浮动

---

## 8. 验收标准

1. 第一次来的人 5 秒内能说出「这产品是干嘛的」
2. 不点任何按钮，也能从 ②③ 看懂「什么值得孵化、怎么孵化」
3. 老用户一屏内能看到「现在该处理哪一颗」
4. 移动端 375px 无横向溢出
5. 首屏不出现空统计（无数据时用引导替代）
